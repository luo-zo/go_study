状态：目前只讲到 GET /shops 的流程、城市筛选和空结果。没有完成模块代码和实际测试。

## 为什么先使用内存

先集中理解路由、参数和响应，再引入数据库。商户数据暂存 Go 变量；程序重启后，运行中新增或修改的数据不会自动保留。

|---|---|---|---|
| 1 | 南宁火锅店 | 南宁 | hotpot |
| 2 | 柳州烧烤店 | 柳州 | bbq |
| 3 | 南宁甜品店 | 南宁 | dessert |

## 查询全部

```http
GET /shops
```

```text
客户端请求 → Gin 匹配路由 → 读取内存列表 → 返回 HTTP 200 和列表
```

## 按城市筛选

```http
GET /shops?city=南宁
```

```text
读取 city → 遍历商户 → 保留城市匹配项 → 返回结果
```

```json
{
  "data": [
    {"id": 1, "name": "南宁火锅店", "city": "南宁", "category": "hotpot"},
    {"id": 3, "name": "南宁甜品店", "city": "南宁", "category": "dessert"}
  ]
}
```

没有匹配商户通常仍返回 200：

```json
{"data": []}
```

这表示查询成功但结果为空。列表无匹配项与“指定 ID 的详情不存在”是不同情况，详情接口后续再讲。
